# v0.10.0: Dry-run MCP tools with policy validation

Version v0.10.0 adds a deliberately limited active affordance layer on top of the read-only SDC-to-MCP resource gateway. The new MCP tools validate action proposals but do not execute SDC operations.

## Scope

The release keeps the device-facing side safe by enforcing:

- `tool_mode: dry-run`
- `write_operations_allowed: false`
- `executed: false` for every tool result
- policy validation before accepting a proposal
- audit logging of every dry-run tool call

The dry-run tool surface is intended for research experiments on agentic action proposals, not for medical device control.

## Tools

The default policy file exposes three dry-run tools:

- `prepare_set_fio2(device_id, value)`
- `prepare_set_peep(device_id, value)`
- `prepare_acknowledge_alarm(device_id, alarm_handle)`

All three require human approval and never send SDC SetService, ActivateOperation, or alarm acknowledgement messages.

## CLI commands

```powershell
sdc-mcp-gateway list-tools --config config/gateway.simulated.dryrun.example.yaml

sdc-mcp-gateway call-tool prepare_set_fio2 `
  --args-json '{"device_id":"sim-ventilator-1","value":45}' `
  --config config/gateway.simulated.dryrun.example.yaml

sdc-mcp-gateway tool-smoke-test --config config/gateway.simulated.dryrun.example.yaml
```

## Expected behavior

Valid dry-run proposal:

```json
{
  "status": "accepted_dry_run",
  "executed": false,
  "requires_human_approval": true,
  "write_operations_allowed": false
}
```

Out-of-range proposal:

```json
{
  "status": "rejected",
  "reason": "value_out_of_range",
  "executed": false
}
```

Wrong target device type:

```json
{
  "status": "rejected",
  "reason": "wrong_device_type",
  "executed": false
}
```
