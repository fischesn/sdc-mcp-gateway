# v0.6.0 Specification: Repeatable Benchmark and Experiment Logging

## Scope

Version 0.6.0 adds a repeatable benchmarking layer for the read-only SDC-to-MCP gateway. The goal is to generate structured experiment artifacts that can later be used for paper tables and plots.

The implementation remains read-only:

- no SDC operation is executed;
- no MCP tool is exported;
- no write operation is allowed;
- simulated providers remain in-process and are not real IEEE 11073 SDC network providers.

## New CLI command

```bash
sdc-mcp-gateway benchmark \
  --config config/gateway.simulated.example.yaml \
  --mie config/sdc_mie.yaml \
  --iterations 20 \
  --warmup 2 \
  --output-dir data/experiment_runs \
  --label simulated-v06
```

The command repeatedly:

1. builds the configured gateway registry;
2. lists all resources;
3. reads all advertised resources;
4. checks the read-only safety boundary;
5. records resource counts, metric counts, alarm counts, active alarms, and timing measurements.

For the simulated adapter, the command advances the simulated scenario time between iterations using `--elapsed-start-s` and `--elapsed-step-s`. This produces deterministic but varying metric values.

## Output files

Each run writes three files to the output directory:

- `<run_id>.jsonl`: one detailed record per warm-up and measured iteration;
- `<run_id>.csv`: tabular iteration data for spreadsheets or plotting scripts;
- `<run_id>.summary.json`: compact summary with latency statistics and safety checks.

Generated files under `data/experiment_runs/` are ignored by Git.

## Measured timings

The benchmark records the following durations in milliseconds:

- `snapshot_build_ms`: adapter snapshot and resource-registry construction;
- `list_resources_ms`: construction of the resource catalogue;
- `read_resources_ms`: reading all advertised resources;
- `read_health_ms`: reading `sdc://health` after the full resource pass;
- `total_ms`: full benchmark iteration duration.

The summary reports min, median, mean, p95, and max for each timing category.

## Safety boundary checks

The summary includes:

```json
"safety_boundary": {
  "all_read_only": true,
  "tools_exported_any": false,
  "write_operations_allowed_any": false
}
```

For v0.6.0 these values must remain unchanged. Any deviation indicates a safety regression.

## Paper relevance

v0.6.0 supports the first reproducible experimental section of the paper:

- resource exposure completeness;
- gateway read latency;
- mapping consistency;
- read-only safety-boundary verification;
- simulated-device baseline for later comparison with real SDC devices.
