# v0.4.0 Specification: Read-only MCP Resource Server

Version v0.4.0 turns the previously console-oriented read-only gateway into a
proper MCP resource surface. The implementation remains deliberately conservative:
no MCP tools are exported, no write operations are allowed, and all resources are
JSON payloads derived from the configured SDC adapter.

## Goals

- expose gateway state through MCP resources;
- keep the same adapter model used by the dummy, simulated, and `sdc11073` paths;
- provide a machine-readable resource catalogue;
- add command-line utilities to inspect the MCP resource surface without an MCP client;
- preserve the read-only safety boundary.

## Non-goals

- no SDC write operations;
- no MCP tools;
- no autonomous device control;
- no clinical use;
- no replacement for real SDC conformance testing.

## Resource surface

The gateway exposes the following top-level resources:

| URI | Meaning |
| --- | --- |
| `sdc://health` | Gateway status, read-only mode, resource count, and safety boundary |
| `sdc://resources` | Machine-readable catalogue of all currently exposed resources |
| `sdc://devices` | List of known SDC providers/devices |
| `sdc://mapping` | Active SDC-MIE mapping document |

For each known device, the following resources are exposed:

| URI pattern | Meaning |
| --- | --- |
| `sdc://devices/{device_id}/metrics` | Mapped read-only metric states |
| `sdc://devices/{device_id}/alarms` | Read-only alarm states |
| `sdc://devices/{device_id}/context` | Patient/location/operator/workflow context references |
| `sdc://devices/{device_id}/mdib/raw` | Raw or normalized MDIB-like snapshot |

## CLI inspection commands

v0.4.0 adds two inspection commands.

List all resources:

```bash
sdc-mcp-gateway list-resources \
  --config config/gateway.simulated.example.yaml \
  --mie config/sdc_mie.yaml
```

Read a single resource:

```bash
sdc-mcp-gateway read-resource sdc://health \
  --config config/gateway.simulated.example.yaml \
  --mie config/sdc_mie.yaml
```

These commands use the same `ResourceRegistry` as the MCP server and are intended
for debugging and automated tests.

## Running the MCP server

Install the optional MCP dependency:

```bash
python -m pip install -e ".[mcp]"
```

Run the server over the default stdio transport:

```bash
sdc-mcp-gateway serve \
  --config config/gateway.simulated.example.yaml \
  --mie config/sdc_mie.yaml
```

The command starts a FastMCP server and registers the read-only resources listed
above. The concrete MCP client configuration depends on the client being used.
For debugging without a client, prefer `list-resources` and `read-resource`.

## Safety boundary

The `sdc://health` resource must continue to report:

```json
{
  "mode": "read-only",
  "tools_exported": false,
  "write_operations_allowed": false
}
```

This is intentional. Tool generation and dry-run validation are deferred to a
later version.
