# v0.7.1: Scenario and alarm-observation correction

Version 0.7.1 is a small corrective release on top of v0.7.0.

## Changes

- The high-airway-pressure scenario now uses a sustained `step` event starting at 30 s instead of a finite pulse. This ensures that the airway-pressure alarm is still active at the end of standard 100-iteration benchmark runs.
- Benchmark summaries now include two additional alarm-observation fields:
  - `active_alarm_count_max`: maximum number of simultaneously active alarms observed during measured iterations.
  - `active_alarm_seen_any`: true if at least one active alarm was observed during measured iterations.
- Benchmark aggregation now preserves and aggregates these fields across runs.

## Rationale

The previous v0.7.0 high-airway-pressure scenario could complete correctly while reporting `active_alarm_count_last = 0` if the pressure episode ended before the last benchmark iteration. This was not a gateway failure, but it made scenario interpretation unnecessarily ambiguous. v0.7.1 keeps the final-state metric while adding `seen_any` and `max` metrics, which are more appropriate for pulse-like or transient alarm scenarios.

## Safety boundary

The release remains strictly read-only:

- no MCP tools are exported;
- no SDC write operations are executed;
- all scenario and benchmark logic operates on simulated or read-only resource snapshots.
