# v0.10.1: Tool argument files for Windows-friendly dry-run calls

Version v0.10.1 is a small usability and reproducibility update for the dry-run MCP tool layer introduced in v0.10.0.

## Motivation

Passing JSON directly as a command-line argument is fragile on Windows PowerShell because quoting rules can alter the JSON string before it reaches the Python CLI. For dry-run tool experiments, this is unnecessary friction and can make documented commands hard to reproduce.

## Change

The `call-tool` command now supports:

```powershell
sdc-mcp-gateway call-tool prepare_set_fio2 `
  --args-file config\tool_args\set_fio2_45.json `
  --config config\gateway.simulated.dryrun.example.yaml
```

The existing `--args-json` option remains available. The two options are mutually exclusive. If neither is given, the tool receives an empty JSON object.

## Example argument files

The release includes example files under `config/tool_args/`:

- `set_fio2_45.json`: valid FiO2 dry-run proposal.
- `set_fio2_150_invalid.json`: invalid FiO2 proposal rejected by range policy.
- `set_peep_10.json`: valid PEEP dry-run proposal.
- `ack_airway_pressure_alarm.json`: dry-run alarm acknowledgement proposal.

## Scope

This release does not change the safety model. Tools remain dry-run only. No SDC operations are executed, write operations remain disabled, and the tool responses must contain `executed: false`.
