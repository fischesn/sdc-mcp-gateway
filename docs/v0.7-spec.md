# v0.7.0: Scenario-based simulation

Version 0.7.0 extends the simulated SDC-like testbed with explicit time-dependent clinical scenarios.

## Goals

- Provide repeatable semantic scenarios for agent and alarm-management experiments.
- Support three initial scenarios: tachycardia, SpO2 drop, and high airway pressure.
- Allow users to create their own scenario YAML files without modifying Python code.
- Preserve the read-only safety boundary.

## Non-goals

- No real IEEE 11073 SDC provider simulation.
- No SDC write operations.
- No MCP tools.
- No clinical decision making.

## Scenario event model

Metric definitions can now include `events`. Supported event types are:

- `step`: fixed target or delta after a start time.
- `ramp`: gradual change between start and end time.
- `pulse`: finite step between start and end time.

Events are applied after the baseline sinusoidal signal and deterministic noise, and before min/max clipping.

## Included examples

- `config/sim.tachycardia.yaml`
- `config/sim.spo2-drop.yaml`
- `config/sim.high-airway-pressure.yaml`

Each scenario includes alarm thresholds that are crossed during the configured time interval.

## Expected validation commands

```bash
pytest -q
sdc-mcp-gateway simulate-snapshot --scenario config/sim.tachycardia.yaml --elapsed-s 60 --mie config/sdc_mie.yaml
sdc-mcp-gateway simulate-snapshot --scenario config/sim.spo2-drop.yaml --elapsed-s 70 --mie config/sdc_mie.yaml
sdc-mcp-gateway simulate-snapshot --scenario config/sim.high-airway-pressure.yaml --elapsed-s 60 --mie config/sdc_mie.yaml
```

For benchmarks:

```bash
sdc-mcp-gateway benchmark --config config/gateway.simulated.tachycardia.example.yaml --mie config/sdc_mie.yaml --iterations 100 --warmup 10 --label tachycardia-v07
```

## Safety status

The gateway remains read-only. `sdc://health` must continue to report:

```json
{
  "mode": "read-only",
  "tools_exported": false,
  "write_operations_allowed": false
}
```
