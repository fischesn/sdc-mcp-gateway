# v0.6.0 Specification: End-to-End MCP Client Smoke Test

Version v0.6.0 adds an end-to-end MCP client smoke test for the read-only gateway.
The goal is to verify not only the internal resource registry and FastMCP server
construction, but also actual MCP protocol interaction between a client and the
stdio server process.

## Scope

v0.6.0 remains strictly read-only:

- no SDC write operation is executed;
- no MCP tools are exported;
- no clinical use is intended;
- the simulated adapter remains an in-process SDC-like testbed, not a real IEEE 11073 SDC provider.

## New command

```bash
sdc-mcp-gateway mcp-client-smoke-test \
  --config config/gateway.simulated.example.yaml \
  --mie config/sdc_mie.yaml
```

The command starts the gateway server as a subprocess using the stdio MCP transport,
opens an MCP `ClientSession`, initializes the client-server session, lists resources,
reads selected resources, and checks that no tools are exposed.

## Checks

The smoke test verifies:

1. the MCP client initializes successfully;
2. `list_resources` returns gateway resources;
3. the static entry resources are present (`sdc://health`, `sdc://resources`, `sdc://devices`, `sdc://mapping`);
4. `read_resource(sdc://health)` succeeds;
5. the read-only safety boundary is intact;
6. `read_resource(sdc://resources)` returns a catalogue;
7. `read_resource(sdc://devices)` returns devices;
8. selected device metric resources are readable and mapped;
9. `list_tools` returns no tools.

## MCP resource registration

The server now registers every currently advertised gateway resource as a concrete
MCP resource. This means that `list_resources` returns the full current catalogue,
including device-specific URIs such as:

```text
sdc://devices/sim-monitor-1/metrics
sdc://devices/sim-ventilator-1/metrics
```

This is useful for agent clients because they can discover concrete resources without
inferring URI parameters from templates.

## Expected result

For the simulated two-device testbed, the expected status is:

```text
status: ok
resource_count: 12
tool_count: 0
```
