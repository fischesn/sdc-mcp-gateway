# v0.9.0 Specification: LLM-backed agent evaluation

v0.9 introduces optional LLM-backed agent evaluation while preserving the v0.8 oracle-agent evaluation harness.

## Goals

- Reuse the same scenario tasks, ground truth, and graders from v0.8.
- Add an LLM resource agent that receives MCP resource context and returns structured JSON answers.
- Support a dependency-light mock backend for CI and reproducible testing.
- Support optional real LLM backends:
  - `llm-ollama` for local Ollama chat models.
  - `llm-openai-compatible` for OpenAI-compatible chat-completion endpoints.
- Keep the gateway strictly read-only: no MCP tools, no write operations.

## CLI examples

Mock backend:

```powershell
sdc-mcp-gateway evaluate-agent-tasks `
  --config config/gateway.simulated.tachycardia.example.yaml `
  --mie config/sdc_mie.yaml `
  --tasks config/agent_eval.tasks.yaml `
  --scenario tachycardia `
  --agent llm-mock `
  --output-dir data/agent_eval `
  --elapsed-s 100
```

## Evaluation path

1. Build the same MCP resource registry used by the server.
2. Serialize device, metric, alarm, and resource catalogue context.
3. Ask the LLM to answer one task at a time as strict JSON.
4. Parse the returned JSON.
5. Grade the response against scenario-specific ground truth.
6. Write JSON, CSV, and Markdown outputs.

## Safety boundary

The LLM receives read-only resource context only. No MCP tools are exposed and no write operations are allowed.
The grader also checks that clinical summaries do not include treatment or device-control recommendations.

## Limitations

- Real LLM outputs are non-deterministic and may require repeated runs.
- The mock backend validates the prompt/parsing/grading path, not model reasoning quality.
- The current context is small and fully included in the prompt. Larger real SDC testbeds may require context selection.
