# v0.8.0 Specification: Agent-Facing Scenario Evaluation

Version v0.8.0 adds an agent-facing evaluation layer on top of the read-only SDC-to-MCP resource surface. The purpose is to evaluate whether the exposed MCP resources support common AI-agent tasks such as device inventory, alarm detection, clinical-state summarization, and resource selection.

## Scope

v0.8 intentionally uses a deterministic `oracle` agent. This is not meant to simulate LLM behavior. Instead, it validates the task definitions, scenario ground truth, resource access pattern, safety checks, and automatic graders before LLM-based agents are introduced.

## New command

```powershell
sdc-mcp-gateway evaluate-agent-tasks `
  --config config/gateway.simulated.tachycardia.example.yaml `
  --mie config/sdc_mie.yaml `
  --tasks config/agent_eval.tasks.yaml `
  --scenario tachycardia `
  --agent oracle `
  --output-dir data/agent_eval `
  --elapsed-s 100
```

The command writes:

```text
data/agent_eval/<run_id>.json
data/agent_eval/<run_id>.csv
data/agent_eval/<run_id>.md
```

## Supported tasks

The default task file is `config/agent_eval.tasks.yaml` and contains four tasks:

1. **Device inventory**: identify exposed SDC providers.
2. **Alarm detection**: determine whether active alarms exist and associate them with device, priority, and semantic metric.
3. **Clinical-state summarization**: summarize the current device state without recommending treatment or parameter changes.
4. **Resource selection**: identify the MCP resource URI needed to inspect relevant device metrics.

## Safety boundary

The evaluation verifies the same read-only boundary as previous versions:

```json
{
  "mode": "read-only",
  "tools_exported": false,
  "write_operations_allowed": false
}
```

No write-capable MCP tools are exported in v0.8.

## Batch execution

A PowerShell helper script is provided:

```powershell
.\scripts\run_agent_evaluation.ps1
```

It evaluates baseline, tachycardia, SpO2-drop, and high-airway-pressure scenarios.

## Intended use in the paper

v0.8 enables a second evaluation axis beyond performance:

- Can an agent identify the exposed devices?
- Can it detect the active alarm in each scenario?
- Can it associate alarms with the correct semantic metric?
- Can it summarize state without unsafe recommendations?
- Can it select the correct MCP resource URI?

This complements the v0.6/v0.7 benchmark results and prepares the transition to LLM-based agent evaluation in a later version.
