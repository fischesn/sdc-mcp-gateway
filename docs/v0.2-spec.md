# Version 0.2.1 Specification: Real SDC Snapshot Adapter

## 1. Purpose

Version 0.2 extends the read-only v0.1 scaffold with a first real `sdc11073` adapter. Version 0.2.1 is a documentation and configuration-hygiene patch: it clarifies which YAML files are part of the repository and which local lab configuration must stay untracked.

The technical goal remains unchanged: discover SDC providers on a selected IPv4 interface, connect to accepted providers, initialize a `ConsumerMdib`, extract a normalized read-only snapshot, and expose that snapshot through the existing `sdc://` MCP resource surface.

This version is still a laboratory and research prototype. It performs no SDC write operation, exports no MCP tools, and does not implement event streaming.

## 2. Scope

Included in v0.2/v0.2.1:

- provider discovery through `sdc11073.wsdiscovery.WSDiscovery`,
- SDC provider filtering through an optional whitelist,
- one-shot connection to discovered providers,
- `ConsumerMdib` initialization,
- defensive extraction of metric states, alarm states, context states, and MDIB summary metadata,
- `discover` CLI command,
- updated `snapshot` command for dummy and real adapters,
- JSONL measurement records for discovery and snapshot runs,
- tests for the extractor, configuration, and dependency handling,
- explicit Git hygiene for local SDC VPN/lab configuration.

Deferred to later versions:

- continuous subscriptions and event-to-resource latency measurement,
- MCP tool generation from Service Control Objects,
- dry-run validation of tool calls,
- Human-in-the-loop approval,
- execution of any SDC operation.

## 4. Configuration and Git Hygiene

The repository contains version-controlled default and example YAML files:

```text
config/gateway.yaml
config/gateway.sdc11073.example.yaml
config/sdc_mie.yaml
config/policies.yaml
config/README.md
```

These files should remain in Git because they document the expected configuration structure.

Real lab settings must go into a local file that is ignored by Git:

```text
config/gateway.local.yaml
```

Create it from the example template:

```bash
cp config/gateway.sdc11073.example.yaml config/gateway.local.yaml
```

Windows PowerShell:

```powershell
Copy-Item config/gateway.sdc11073.example.yaml config/gateway.local.yaml
```

Then edit the local file:

```yaml
sdc:
  adapter: "sdc11073"
  discovery_timeout_s: 5
  local_ip: "YOUR_LOCAL_SDC_VPN_OR_LAB_INTERFACE_IPV4"
  max_devices: 1
  provider_whitelist: []
```

`local_ip` must be the IPv4 address of the network interface on which the gateway process runs. In an SDC VPN, this is normally the VPN adapter address of the gateway host, not the address of a medical device.

The `.gitignore` deliberately ignores only the local instance:

```gitignore
config/gateway.local.yaml
```

Do not ignore `config/*.yaml`, because that would hide the important templates from the repository.

## 5. CLI

List discoverable providers using the local lab config:

```bash
sdc-mcp-gateway discover --config config/gateway.local.yaml
```

Capture and print an MCP resource snapshot:

```bash
sdc-mcp-gateway snapshot --config config/gateway.local.yaml --mie config/sdc_mie.yaml
```

Run the MCP server over the configured adapter:

```bash
sdc-mcp-gateway serve --config config/gateway.local.yaml --mie config/sdc_mie.yaml
```

For dummy development, use `config/gateway.yaml` instead.

## 6. Measurement Records

v0.2 writes JSONL events such as:

```json
{
  "event_type": "sdc_discovery",
  "status": "ok",
  "details": {
    "local_ip": "192.168.1.10",
    "discovered_count": 1,
    "accepted_count": 1,
    "duration_ms": 5042.3
  }
}
```

and:

```json
{
  "event_type": "sdc_mdib_snapshot",
  "status": "ok",
  "details": {
    "provider_epr": "urn:uuid:...",
    "duration_ms": 813.5
  }
}
```

These records are intentionally simple. v0.3 will add event-level latency instrumentation.

## 7. Safety Boundary

v0.2.1 remains read-only. The adapter starts the SDC consumer services to obtain the MDIB, but it does not call any Service Control Object operation. It only reads state and descriptor information. If any write-like operation is needed later, it must be introduced first as a dry-run tool in v0.4 and then guarded by policy and HITL layers in v0.5.

## 8. Definition of Done

v0.2.1 is complete when:

1. dummy mode still works,
2. the package imports without `sdc11073` installed,
3. `sdc11073` is loaded lazily only when the real adapter is selected,
4. `discover` reports provider EPRs in a real lab network,
5. `snapshot` extracts at least an MDIB summary from a real provider,
6. metrics/alarms/context are extracted when the provider exposes matching BICEPS states,
7. all unit tests pass without real SDC hardware,
8. the repository contains YAML templates but excludes `config/gateway.local.yaml`.
