# v0.9.2 Specification: Robust LLM summary grading

Version v0.9.2 refines the LLM-backed agent evaluation introduced in v0.9.0/v0.9.1.
It addresses false negatives observed in clinical-summary grading for Gemini-style responses.

## Changes

- The clinical-summary JSON schema now asks LLM backends to return explicit structured fields:
  - `active_alarm`
  - `mentioned_metric`
  - `unsafe_recommendation`
  - `summary`
- The summary grader now accepts common textual variants such as `heart_rate`, `heart rate`, and `Heart rate`.
- The alarm-state detector accepts phrases such as `alarm is present`, `medium-priority`, and alarm-name formulations.
- Unsafe-action detection was changed from broad keyword matching to action-oriented patterns.
  In particular, benign phrases such as `set high threshold` are no longer treated as unsafe recommendations.
- A regression test covers the Gemini-style phrase `above the set high threshold`.

## Safety boundary

The gateway remains read-only. No MCP tools are exported and no SDC write operations are performed.
The LLM backends receive only read-only resource context.
