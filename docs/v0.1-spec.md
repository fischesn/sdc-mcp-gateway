# Version 0.1 Specification: Read-only SDC-to-MCP Gateway

## 1. Purpose

Version 0.1 establishes the smallest useful research prototype for exposing IEEE 11073 SDC device state through the Model Context Protocol (MCP). The prototype is intentionally read-only. It is meant to support architectural validation, early measurements, and later paper experiments.

## 2. Non-goals

The following are explicitly out of scope for v0.1:

- no execution of SDC Service Control Objects (SCOs),
- no MCP tools for device manipulation,
- no autonomous or semi-autonomous clinical action,
- no use in clinical operation,
- no regulatory claim,
- no production-grade authentication or authorization,
- no dependency on a specific commercial SDC stack.

## 3. High-level architecture

```text
+------------------+      +--------------------+      +---------------------+
| SDC Provider(s)  | ---> | SDC Consumer Layer | ---> | Local Gateway State |
+------------------+      +--------------------+      +----------+----------+
                                                           |
                                                           v
                                                +----------------------+
                                                | SDC-MIE Mapping      |
                                                +----------+-----------+
                                                           |
                                                           v
                                                +----------------------+
                                                | MCP Resource Surface |
                                                +----------------------+
```

## 4. Components

### 4.1 SDC Consumer Layer

Responsibilities:

- discover SDC providers,
- obtain or receive MDIB state,
- normalize device snapshots into internal Python models,
- expose device, metric, alarm, context, and raw-MDIB state to the gateway.

v0.1 contains:

- `DummySdcConsumer` for deterministic tests and demos,
- `Sdc11073Consumer` as a stub for the later real adapter.

### 4.2 Local Gateway State

The local gateway state is a cache-like representation of the latest known SDC information. In v0.1 this is static for dummy data and snapshot-based for future real SDC data. Event streaming is deferred to v0.2.

### 4.3 SDC-MIE Mapping

The mapping layer loads a YAML file that assigns stable semantic names, units, safety classes, and descriptions to SDC metric or operation codes.

In v0.1, mappings are used only for read-only resources. Missing mappings are not fatal; the element remains accessible through its raw identifier and is reported as unmapped.

### 4.4 MCP Resource Surface

The MCP server exposes custom `sdc://` resources:

| Resource URI | Meaning |
|---|---|
| `sdc://devices` | List of known devices |
| `sdc://devices/{device_id}/metrics` | Metrics for one device |
| `sdc://devices/{device_id}/alarms` | Alarm states for one device |
| `sdc://devices/{device_id}/context` | Patient/location/device context |
| `sdc://devices/{device_id}/mdib/raw` | Raw or normalized MDIB snapshot |
| `sdc://mapping` | Loaded SDC-MIE mapping |
| `sdc://health` | Gateway health and configuration status |

## 5. Logging and measurement

v0.1 records structured JSONL audit/measurement entries for resource accesses and snapshots. Later versions will add event-to-resource latency metrics.

Minimum fields:

```json
{
  "timestamp": "2026-05-21T12:00:00Z",
  "event_type": "resource_read",
  "resource_uri": "sdc://devices/dummy-monitor-1/metrics",
  "status": "ok",
  "mapping_version": "0.1-example"
}
```

## 6. Definition of Done for v0.1

v0.1 is considered complete when:

1. the repository installs locally with `pip install -e .[dev]`,
2. tests pass,
3. dummy devices are exposed as internal resources,
4. MCP server creation works if the MCP SDK is installed,
5. missing mappings are reported but do not crash the gateway,
6. no write operation exists in the MCP surface,
7. documentation clearly states the non-clinical status.

## 7. Planned next versions

- v0.2: real `sdc11073` provider discovery and MDIB snapshot extraction,
- v0.3: event subscriptions and latency instrumentation,
- v0.4: dry-run MCP tool generation from SCO descriptors,
- v0.6: policy engine and HITL workflow,
- v0.6: controlled execution in an isolated test network.
