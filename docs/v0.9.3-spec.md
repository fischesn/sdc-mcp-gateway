# v0.9.3 Specification: Stricter LLM Resource Selection

Version v0.9.3 refines the LLM-backed agent evaluation path. In v0.9.2, Gemini could answer the baseline resource-selection task with a plausible example URI for the patient monitor although the task expected the ventilator metrics resource. This was a real agent-selection error caused by an ambiguous prompt in a multi-device scenario.

## Changes

- The resource-selection task prompt now asks for exactly one existing URI for the target device metrics.
- The LLM prompt includes `selection_constraints` with:
  - `target_device_id`,
  - inferred `target_device_type`,
  - `required_resource_kind: metrics`,
  - `return_exactly_one_existing_uri`,
  - `do_not_return_examples`.
- The LLM resource context now uses an enriched resource index. Each resource entry includes:
  - `uri`,
  - `name`,
  - `description`,
  - `device_id`,
  - inferred `device_type`,
  - `resource_kind`,
  - `read_only`.

## Safety boundary

This version does not add MCP tools and does not enable write operations. All LLM-facing tasks remain strictly read-only.

## Expected regression behavior

For the baseline scenario, a Gemini run should select:

```text
sdc://devices/sim-ventilator-1/metrics
```

rather than the patient monitor metrics URI.
